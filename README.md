# BLORIQ

초록색 목표 블록을 한 칸씩 밀어 별 모양 출구로 보내는 퍼즐입니다. 블록이 비운 칸에 한 턴 동안 잔상이 남아 다음 이동을 막습니다. 현재는 핵심 재미와 학습 흐름을 검증하기 위한 **25개 스테이지 프로토타입**입니다. 로그인과 서버 없이 Android에서 오프라인으로 플레이하는 것이 목표이며 실기기 오프라인 테스트는 아직 필요합니다.

현재 규칙을 기준으로 정리한 후속 제작 지시와 완료 기준은 [개발 마스터 프롬프트 v3](docs/ECHO_BLOCK_MASTER_PROMPT_V3.md)를 참고하세요.

첨부된 상용 게임 개발 방향과 현재 게임 방식의 선택 근거는 [BLORIQ 제품 방향](docs/BLORIQ_PRODUCT_DIRECTION.md)에 정리했습니다.

## 게임 방법

- 블록을 상하좌우로 드래그하면 한 번에 한 칸 이동합니다. 초록 블록을 별까지 보내면 클리어합니다.
- 성공적으로 이동하면 출발 칸에 잔상이 생깁니다. 이전 잔상은 다음 이동을 판정할 때까지 장애물로 남고, 그 이동이 끝나면 새 잔상으로 교체됩니다.
- 스위치가 있는 스테이지에서는 스위치 위의 잔상이 문을 엽니다. 잔상이 남아 있는 동안 문으로 들어갈 수 있고, 다음 이동을 마치면 이전 잔상이 사라지며 문이 닫힙니다. 블록이 문 위에 있을 때 문이 닫혀도 블록을 문 밖으로 이동할 수 있습니다.
- 막힌 칸으로 드래그하거나 가만히 기다리는 것은 턴을 소비하지 않습니다.
- Undo는 블록 위치와 잔상을 함께 복원하고 Restart는 현재 스테이지를 처음부터 시작합니다. 이동할 수 있는 수가 없으면 되돌리기 버튼이 안내됩니다.
- 우측 상단의 물음표에서 게임 방법을 확인하고, 소리 아이콘과 음표 아이콘으로 효과음과 BGM을 각각 켜거나 끌 수 있습니다. 설정은 기기에 저장됩니다. BGM은 보드를 처음 터치한 뒤 시작합니다. 진동을 별도로 끄는 설정은 아직 없습니다.

첫 스테이지는 조작을, 두 번째는 잔상을, 세 번째 이후에는 블록을 교대로 움직이거나 우회하는 방법을 연습하도록 구성했습니다. 11~13단계는 선택과 순서를 고민하는 도전 퍼즐이며, 14~15단계에서 잔상 스위치와 문을 체험합니다. 16~25단계는 빈칸을 교환하고 후퇴하거나 스위치 타이밍을 고려하는 후반 도전입니다. 블록을 드래그하면 이동 가능 여부와 다음 잔상, 문 상태 변화가 미리 표시됩니다. 클리어 후 별과 개인 최고 기록을 확인하고, 해결 과정을 리플레이하거나 결과를 추상 포스트카드로 공유할 수 있습니다. 재미와 난이도는 실제 사용자 테스트로 확인해야 합니다.

## 실행 방법

Flutter stable SDK가 필요합니다. 이 프로젝트의 개발 기준은 Flutter 3.47.8 / Dart 3.13.7입니다. 설치는 [Flutter 공식 문서](https://docs.flutter.dev/get-started/install)를 참고하세요. Chrome으로 실행할 때는 Android SDK가 필요하지 않습니다.

다른 컴퓨터에서 처음 시작한다면 `git clone https://github.com/corcoidum/bloriq.git`으로 저장소를 내려받고 `cd bloriq`으로 이동합니다. 이미 저장소가 있다면 본인 작업을 확인한 후 `git pull --ff-only`로 최신 변경을 가져옵니다.

프로젝트 폴더에서 PowerShell 또는 터미널을 열고:

```powershell
flutter --version
flutter doctor -v
flutter pub get
flutter gen-l10n
flutter devices
flutter run -d chrome
```

Chrome 창이 열리면 마우스로 블록을 드래그해 플레이합니다. 종료하려면 실행 중인 터미널에서 `q`를 누릅니다. 최초 실행은 의존성과 웹 빌드 도구 다운로드로 시간이 걸릴 수 있습니다.

Android 실행에는 Android SDK, 호환 JDK, USB 디버깅을 켠 기기 또는 에뮬레이터가 필요합니다. [Android 환경 설정](https://docs.flutter.dev/platform-integration/android/setup) 후 `flutter devices`에서 기기 ID를 확인하고 `flutter run -d <기기_ID>`를 실행합니다. `flutter doctor`가 Android 라이선스 동의를 요청하면 `flutter doctor --android-licenses`를 실행합니다.

Android debug APK가 필요하면 `flutter build apk --debug`를 실행합니다. 결과는 `build/app/outputs/flutter-apk/app-debug.apk`에 생성됩니다. 이 파일은 테스트용이며 스토어 배포용이 아닙니다.

Android SDK 설치, 휴대폰 연결, APK 설치 및 확인할 항목은 [Android 휴대폰 테스트 안내](docs/ANDROID_PHONE_TEST.md)를 참고하세요. 2026-10-28 작업 환경에서는 Android SDK가 감지되지만 Command-line Tools가 없고 라이선스 상태를 확인할 수 없어 Android 환경 설정과 실기기 확인이 필요합니다.

## 검증

```powershell
flutter gen-l10n
flutter analyze
flutter test
python tools/validate_levels.py
```

독립 Python 검증기는 각 스테이지의 해결 가능성과 최단 이동 횟수를 BFS로 확인합니다. 일반 스테이지는 잔상을 무시한 경우의 최단 이동과 비교하고, 스위치 스테이지는 문을 계속 닫으면 해결할 수 없는지 확인합니다. Flutter 테스트는 이동 판정, 잔상, Undo/Restart, solver와 첫 10개 스테이지의 드래그·화면 전환을 검증합니다. 자동 테스트만으로 터치 감도, 사운드 출력, 실기기 성능이나 첫 사용자 이해도를 보장하지는 않습니다.

## 데이터와 범위

`assets/levels/levels.json`에서 `startPosition`은 목표 블록 시작 위치, `exitPosition`은 출구, `blocks`는 일반 블록, `obstacles`는 고정 장애물입니다. 잔상 스위치 스테이지는 `specialRules`에 `echoGate`와 스위치·문 좌표를 지정합니다. 좌표 `(0, 0)`은 왼쪽 위입니다. `minimumMoves`는 잔상까지 포함해 검증한 최단 이동 횟수입니다. 새로운 스테이지를 추가하면 위 테스트와 검증기를 다시 실행하세요.

계정, 서버, 광고, 결제 기능은 없습니다. 스테이지별 최고 이동 수, 최고 별, 완료 횟수는 기기 내부에 저장되며 스테이지 메뉴에서 최고 별을 볼 수 있습니다. 앱 데이터 삭제나 앱 제거 시 기록이 사라질 수 있습니다. 포스트카드에는 스테이지 번호와 결과만 들어가며 실제 퍼즐 이동 경로는 포함되지 않습니다. 공유를 선택하면 기기의 시스템 공유 창이 열립니다. 효과음과 BGM은 앱에 포함된 합성 음원으로 오프라인에서 재생되며 기기의 오디오 설정에 영향을 받습니다. Android 아이콘과 서명은 출시용이 아닙니다. 실기기 사용자 테스트, 접근성 검토 및 정식 출시 준비는 후속 작업입니다.
